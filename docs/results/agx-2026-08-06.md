# AGX Validation — 2026-08-06

This record covers the extracted three-repository dependency chain flashed on
an Orin AGX P3701-0000 development kit:

- Ghaf PR 2095 revision `4ebc79cb2eca1d516c7b577275ceef55f966f5a7`;
- manager PR 1 revision `55a8e43db1b88492d8d19b550827e6721f668377`;
- examples PR 1 revision `ca968b2588a36cbd16429d4e0410b8427888130d`;
- image `/nix/store/wvrqhb0zkqfwfydvs958fqqp1232xnd5-nixos-image-sd-card-26.11.20260726.624af66-aarch64-linux.img.zst-aarch64-unknown-linux-gnu`.

## Functional Results

- CUDA reported 16 SMs and the manager created two 8-SM contexts.
- The default 4-SM capability probe passed with an 8-SM remainder. The exact
  `--min-sm-count 8` probe passed with two 8-SM groups and no remainder.
- Direct `nvidia.com/gpu=all` CDI completed a real CUDA kernel.
- Managed CDI exposed no direct GPU nodes, rejected direct CUDA, and completed
  a manager-submitted burn.
- Two concurrent 20-second burns completed 123 validated iterations per slot.
- A queued same-slot job ran after cancellation of the active job.
- A 30-minute two-slot burn completed 11,137 validated iterations on each
  slot with identical validation samples.
- Manager and GPU-VM restart counts remained zero.
- No relevant nvgpu fault, timeout, or Xid was observed.
- GPU-VM had no failed systemd units after the run. NetVM remained reachable
  with 1 Gbps/full-duplex carrier.

The host retained a failed `ghaf-load-ftpm-module.service` after first boot.
The GPU-VM and manager did not depend on that service, and this validation did
not change or diagnose the host fTPM configuration.
