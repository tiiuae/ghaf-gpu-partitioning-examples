# Runtime Manifest And Result Format

`/etc/ghaf-gpu-partitioning-example/runtime.json` is generated by Nix. It
records schema version 1, target name, source revisions, pinned L4T and CUDA
versions, expected compute capability, CDI contract, manager protocol, and
plugin ABI. It contains expectations, not claims about a running device.

`gpu-partition-example-runtime-info` combines that manifest with Docker, CDI,
and manager observations. `--probe` additionally creates and destroys two
temporary Green Contexts and records CUDA driver/device information. It refuses
the probe while manager jobs are active.

`gpu-partition-example-collect-results --output DIR` writes:

- `runtime.json`;
- `plugins.txt` and `manager-status.txt`;
- `failed-units.txt`;
- `manager-journal.txt`;
- `kernel-diagnostics.txt`; and
- aggregate `results.json` using schema version 1.

The collector intentionally excludes the process environment, SSH options,
Docker credentials, tokens, and unrelated journals. An operator must collect
host `microvm@gpu-vm.service` restart state separately because GPU-VM cannot
authoritatively observe its owning host service.

Schema version 1 is append-only: consumers must ignore unknown fields. Rename
or reinterpret an existing field only with a new schema version.
